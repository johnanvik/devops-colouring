# Sprint Planning

You will have two responsibilites this sprint:

1. Handle requests to deploy products to production.
1. Implement a code freeze near the end of the sprint.
   - **A code freeze happens for the last two minutes of the sprint.**

Be warned - you may not be busy this sprint.

## What is a code freeze?

A _code freeze_ is a period during software development when no new code changes are allowed, aimed at stabilizing the codebase before a major release or milestone. This practice helps ensure that the software remains stable and ready for deployment by focusing on testing and debugging existing code.

# Sprint Execution

1. Monitor the `System Administration` board for deployment packages with a `To Deploy` status.
   - If not in a code freeze:
     - Set **Status** of the product request to `In Production`
   - If in code freeze:
     - Add the label `Code Freeze` to the product request.
